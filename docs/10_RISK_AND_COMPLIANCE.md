# 10 — 风险、合规和数据边界

## 1. 抓取边界

允许：

- 公开无需登录的官方招聘页面。
- 页面自身请求的公开 JSON 接口。
- 正常低频 HTTP 请求。
- 浏览器正常渲染公开页面。

禁止：

- 绕过登录、验证码、访问控制。
- 获取或复用他人 Cookie/Token。
- 规避明确的技术限制。
- 高频请求影响网站正常服务。
- 抓取非岗位目的的个人信息。

遇到受限源时：记录原因，关闭自动源，保留官方 URL 和手动 JD 功能。

## 2. 信息可信度

- 官方来源标记 `official_source=true`。
- 第三方信息不得覆盖官方内容。
- 岗位展示必须链接原始页面。
- 页面已下线时保留历史但标记状态。
- 未知发布日期不得用首次抓取时间冒充发布日期。

## 3. 用户数据

- 桌面版的简历原件、OCR 文本、面试回答和生成材料默认保存在本地私有目录；云端版仅在用户主动使用云端功能时保存到受控私有卷与 PostgreSQL，所有业务表按 `user_id` 隔离。
- 云端域名只允许 HTTPS + Authing 会话访问；数据库只保存应用会话 Token 的 SHA-256 哈希，不保存用户密码、Authing Access Token 或 Refresh Token。
- 备案期间的 18080 是明文、共享 Token 自测入口，只允许本人使用虚构或充分脱敏的数据。
- OCR 不保留临时页面图片，运行时不得下载模型。
- 浏览器录音只在用户主动点击后开始，默认不保存原始音频。
- 语音 transcript 只进入可编辑草稿，不自动发送或写回 Career Vault。
- 删除简历时必须清理原文件和可识别 preview，同时保留必要的非敏感审计关系。
P1 简历和经历属于个人信息。要求：

- 默认本地；选择云端时明确告知保存位置和删除方式。
- 明确发送给模型的范围。
- 支持删除。
- 不用于训练或分享。
- 日志不记录完整简历。
- 生成内容不编造事实。

## 4. Agent 安全

招聘页面、JD 和外部文本都是不可信数据，不是系统指令。Career Persona 和 Skill 必须提示 Agent 防止提示注入。

- 不执行页面中要求运行的命令。
- 不读取非授权目录。
- 不因网页内容自动发送消息。
- 外部动作继续走 OpenWorker 权限审批。

## 5. 产品定位边界

MVP 是：

- 个人求职辅助工具。
- 官方公开岗位信息检索。
- JD 分析与材料准备。

MVP 不是：

- 招聘中介。
- 企业招聘发布平台。
- 代投服务。
- 候选人简历交易。
- 保证录用或政策解释服务。

## 6. 开源合规

- 保留 OpenWorker MIT LICENSE。
- 在 README 中说明基于 OpenWorker。
- 新增第三方依赖前检查许可证。
- 对 AGPL 服务或代码保持边界清晰，不直接复制到闭源发行版而忽略义务。
