# 01 — 产品需求文档（MVP）

> 本文保留最初岗位发现 MVP 的需求基线。当前产品已经扩展到 Career Vault、岗位
> 匹配、申请材料、申请跟踪和模拟面试；当前范围以
> `00_SCOPE_AND_DECISIONS.md` 和 `docs/README.md` 为准。

## 1. 背景

中国 AI/互联网岗位分散在公司官网、招聘 SaaS 页面、动态前端和招聘公告中。用户通常需要重复浏览不同官网、复制 JD、手工比较岗位，并为每个岗位重新组织材料。产品希望借助 OpenWorker 的本地 Agent Harness，将岗位数据能力和求职任务执行结合起来。

## 2. 目标用户

第一用户就是项目开发者本人，并扩展到：

- 在校本科生、硕士生。
- 寻找国内 AI 产品、Agent、算法、开发、数据岗位的求职者。
- 关注校招、实习和部分社招岗位的人群。
- 希望保留私人简历在本地的用户。

## 3. 核心用户任务

### JTBD-01：分析任意 JD

用户粘贴 JD 文本或 URL，希望系统识别岗位、职责、要求、地点、招聘类型和关键技能，并保存原始文本与结构化数据。

### JTBD-02：发现新岗位

用户希望查看最近新增的 AI/互联网职位，不需要逐一访问每家公司官网。

### JTBD-03：理解岗位变化

用户希望知道岗位是否修改了要求、城市、描述、截止日期，或者已经下线。

### JTBD-04：让 Agent 使用岗位数据

用户希望在 OpenWorker 中直接说“找最近新增的 AI 产品实习岗位”或“分析这个 JD”，由 Career Agent 调用 Career MCP 完成。

### JTBD-05：获得可保存的结果

每次重要分析应生成一个 Markdown 文件，后续可扩展到 DOCX/PDF 和完整申请材料包。

## 4. 功能需求

### F-001 Career Persona

- 在 OpenWorker Personas 中显示 Career Agent。
- 使用 knowledge family 和 deliverable workspace。
- 启用文件、搜索、Shell、Todo 等已有能力。
- 能使用 Career Skills 与 Career MCP。
- 系统提示必须禁止编造用户经历、岗位要求和公司信息。

验收：用户可创建 Career 会话并正常运行一个只读任务。

### F-002 Career Skills

首批 Skill：

1. `career-jd-analysis`
2. `career-job-search`
3. `career-application-packet`（先定义规范，P1 才实现全部）

Skill 应描述工作流程、输出格式、事实约束和工具使用方式，不承载业务数据库代码。

### F-003 Career MCP

提供稳定、领域化的工具契约。P0 工具：

- `health_check`
- `get_mock_jobs`
- `import_manual_jd`
- `get_job`
- `search_jobs`
- `list_recent_job_events`
- `crawl_source`
- `list_sources`

P1 工具：

- `create_candidate_profile`
- `import_resume`
- `match_job_to_profile`
- `create_application_workspace`

### F-004 手动 JD

输入：

- 必填：原始文本。
- 可选：来源 URL、公司、岗位名。

处理：

- 保留原始文本。
- 去除重复空白和明显页面噪声。
- 提取标准字段。
- 字段置信度不足时返回空值，不猜测。
- 返回用户确认所需摘要。
- 确认后保存为 `manual` 来源岗位。

### F-005 官方岗位源

每个数据源包含：

- 公司 ID、名称、官方招聘入口。
- 数据源类型。
- Adapter 类型。
- 是否启用。
- 抓取周期。
- 使用条款或风险备注。
- 最近成功和失败状态。

### F-006 岗位标准化

必须标准化：

- 公司。
- 外部岗位 ID。
- 岗位名称。
- 部门。
- 城市。
- 招聘类型。
- 用工类型。
- 职责。
- 要求。
- 原始完整 JD。
- 发布时间、截止时间。
- 详情 URL、申请 URL。
- 首次发现、最近确认、内容哈希、状态。

### F-007 去重与版本

优先使用公司官方稳定岗位 ID；没有时使用规范化来源 URL；仍没有时使用公司、标题、地点等字段生成自然键。

内容哈希变化时：

- 创建新 JobVersion。
- 生成 changed 事件。
- 保存字段级 diff。

岗位连续多个成功抓取周期未出现，才可判定下线。单次网络或解析失败不得下线岗位。

### F-008 搜索

支持：

- 关键词。
- 公司。
- 城市。
- 招聘类型。
- 状态。
- 首次发现时间。
- 最近变化时间。

默认只返回 active 岗位，按最近变化或首次发现倒序。

### F-009 Agent 交付物

Career Agent 至少可生成：

```text
artifacts/<company>-<job>-job-brief.md
```

包括：

- 岗位基本信息。
- 原始来源。
- 职责与要求。
- 关键技能。
- 变化时间线。
- 明确的缺失字段。

### F-010 调度

MVP 可采用 APScheduler 或简单 CLI + cron。要求：

- 支持单源手动运行。
- 支持全部启用源运行。
- 每次运行有 CrawlRun 记录。
- 失败不影响其他源。
- 同一源避免并发重复执行。

## 5. 非功能需求

### 可靠性

- 抓取任务幂等。
- 重复运行不产生重复岗位。
- Adapter 解析异常可定位到数据源和页面。
- 数据库写入使用事务。

### 性能

MVP 数据量有限，不要求分布式。搜索普通查询应在个人电脑上快速响应。动态浏览器只在必要源启用。

### 可维护性

- 每个 Adapter 有 fixture。
- 解析逻辑与网络请求可分别测试。
- Source 配置与代码解耦。
- 所有状态枚举集中定义。

### 隐私

- 岗位是公开数据。
- 用户简历属于私人数据，P1 默认本地保存。
- 模型调用前明确哪些内容会发送给模型供应商。

## 6. 关键交互示例

### 示例 A：手动 JD

用户：

> 分析下面这个 AI 产品经理实习 JD，并保存到岗位库。

Agent：

1. 加载 JD 分析 Skill。
2. 调用 `import_manual_jd`。
3. 展示结构化摘要与缺失字段。
4. 生成岗位分析 Markdown。

### 示例 B：查询岗位

用户：

> 找最近 7 天新增的北京 AI 产品实习岗位。

Agent 调用 `search_jobs`，按条件返回，并生成简报。

### 示例 C：查看变化

用户：

> 字节跳动最近有哪些岗位更新了要求？

Agent 调用 `list_recent_job_events`，读取 changed 事件和字段 diff。

## 7. MVP 完成定义

- OpenWorker 扩展链路通过。
- 手动 JD 流程通过。
- 至少三个稳定官方来源通过；具体公司不作为硬门槛。
- 数据去重和版本测试通过。
- Agent 能生成岗位简报。
- 本地一条命令或清晰的两进程方式可运行。

以上初始定义已经完成。后续产品 Gate：

- 岗位和简历结论均有可追溯证据。
- Career Vault 私有存储、离线 OCR 和删除边界通过。
- 申请包与定制材料不能越过已确认事实。
- 模拟面试在标准 Conversation 中完成多轮深挖和复盘。
- 语音识别只生成可编辑草稿，不自动发送。
