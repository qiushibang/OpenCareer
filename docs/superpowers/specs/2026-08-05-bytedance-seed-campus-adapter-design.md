# ByteDance Seed Campus Adapter Design

## Goal

Add a production source for ByteDance's public `2027届Seed大模型人才校招`
project without claiming coverage of all ByteDance jobs or reproducing the site's
request signature.

## Source Contract

- Official page: `https://jobs.bytedance.com/campus/position`
- Public project ID: `7621018151002507573`
- Source slug: `bytedance-seed-campus`
- Current live count: 85 jobs in 9 pages of 10
- Listing response:
  `POST /api/v1/search/job/posts`, generated by the official page
- Required query properties:
  `portal_type=3`, exact `subject_id_list`, `limit=10`, monotonic `offset`
- Every job must identify the exact project in `job_subject.name.zh_cn`.

The full campus source has 7,387 jobs and the experienced source is capped at
10,000 results. Those sources cannot be completed inside the MCP 120-second
limit and are explicitly outside this Adapter.

## Architecture

`crawler/bytedance.py` contains two independent parts:

1. Pure parsing and pagination validation for captured JSON payloads.
2. A Playwright transport that opens public project page URLs and waits for the
   listing response generated by the first-party page.

`ByteDanceSeedCampusAdapter` accepts an injected page fetcher for offline tests.
The default fetcher lazily imports the existing OpenWorker `browser` optional
dependency. The Adapter emits existing `JobSnapshot` values; `CrawlerService`
continues to own persistence and state transitions.

## Browser Boundary

- Use a fresh headless Chromium context per crawl.
- Do not load persistent browser state or user profiles.
- Do not read, log, save, replay, calculate, or attach `_signature`.
- Do not attach credentials, login state, or caller cookies.
- Navigate only to `jobs.bytedance.com/campus/position` with the exact public
  project filter and page number.
- Abort images, media, and fonts to reduce crawl time.
- Stop on login, CAPTCHA, 401, 403, 429, 5xx, unexpected host, missing response,
  or a total above 200 jobs / 20 pages.
- Close browser and context on every success or failure.

## Mapping

- `external_job_id`: numeric string `id`
- `title`: non-empty `title`
- `source_url`:
  `https://jobs.bytedance.com/campus/position/<id>/detail`
- `description_raw`: labelled `职位描述`, `职位要求`, `职位 ID`, and project
- `location_raw`: non-empty `city_list[*].name` joined by `、`
- `recruitment_type`: `internship` for `实习`, otherwise `campus`
- `observed_at`: one UTC timestamp for the entire crawl

The human-readable `code` is retained in the description but is not the source
identity because the numeric `id` is the detail-route key.

## Failure Protection

The entire crawl fails without returning partial jobs when:

- the envelope code is not zero;
- `count` is invalid or changes between pages;
- page size, offset, page count, or final item count is inconsistent;
- a job is missing ID, title, description, requirement, or exact project;
- IDs repeat within or across pages;
- a detail URL leaves the verified host and route;
- Playwright is unavailable or the public page cannot produce the response.

No successful snapshot set means the existing service will not apply
missing/offline transitions.

## Testing And Acceptance

Offline fixtures contain two reduced real jobs and no signature, Cookie, token,
or personal data. Tests cover envelope parsing, field mapping, exact project,
duplicates, pagination consistency, injected transport, registry exposure, and
the existing crawler pipeline.

Live acceptance requires:

1. exactly the currently reported count with unique numeric IDs;
2. complete title, description, requirement, location, and official URL;
3. completion inside 120 seconds;
4. real MCP `dry_run=true` success;
5. GUI `list_sources` exposure after restart.

If the live contract requires persistent state, signature handling outside the
first-party page, or exceeds the safety limits, the Adapter remains disabled.
