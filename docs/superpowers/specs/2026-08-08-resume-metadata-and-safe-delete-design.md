# 简历重命名、目标岗位标签与安全删除设计

## 目标

允许用户为简历库中的每份简历设置易识别的名称和目标岗位标签，并安全删除单份简历文档，同时保留已确认进入共享求职档案的真实事实与来源审计。

## 数据模型

Career 数据库升级到 schema v5，在 `resume_imports` 增加：

- `display_name TEXT`：用户可编辑的简历名称。
- `target_roles_json TEXT NOT NULL DEFAULT '[]'`：目标岗位短标签。
- `deleted_at TEXT`：非空表示该简历文档已被用户删除。

迁移规则：

- 现有记录的 `display_name` 回填 `original_filename`。
- 现有记录的目标岗位标签为空数组。
- 现有记录保持未删除状态。
- `original_filename` 保留原文件真实名称，不随重命名变化。

## 元数据规则

### 简历名称

- 去除首尾空白。
- 长度为 1–80 个字符。
- 允许中文、英文、数字和常用标点。
- 名称不要求唯一，简历 ID 才是稳定标识。

### 目标岗位标签

- 每份简历最多 10 个。
- 每个标签去除首尾空白后长度为 1–30 个字符。
- 空标签被丢弃。
- 按输入顺序去重。
- 标签是用户自定义文本，不绑定岗位数据库 ID，岗位下线后仍可保留用户意图。

## 安全删除

单份删除采用软删除：

1. 请求必须携带当前 `display_name` 作为精确确认文本。
2. 删除该简历的私有原文件。
3. 数据库将 `deleted_at` 写为当前时间。
4. 清空 `extracted_text`，避免保留可恢复的简历全文。
5. 删除该 import 对应的 `resume_previews`，使结构化简历文档内容不再可读。
6. 保留 `resume_imports` 最小审计行、`candidate_facts` 和 `profile_versions`，保证已确认事实来源和版本历史外键有效。
7. 列表、详情、版本和原文件 API 均不返回已删除简历。
8. 其他简历和共享候选人事实不受影响。

若删除当前共享档案最新版本所引用的简历，旧的兼容接口 `/v1/career/profile/original` 将返回 `ORIGINAL_NOT_FOUND`，但 `/v1/career/profile` 继续可读。新的多简历页面只使用按简历 ID 的接口。

## API

### 更新元数据

`PATCH /v1/career/resumes/{resume_id}`

请求：

```json
{
  "display_name": "AI 产品经理定制简历",
  "target_roles": ["AI 产品经理", "Agent 产品经理"]
}
```

成功返回更新后的简历摘要。不存在或已删除返回 `RESUME_NOT_FOUND`；校验失败返回 `INVALID_INPUT`。

### 删除单份简历

`DELETE /v1/career/resumes/{resume_id}`

请求：

```json
{
  "confirm_name": "AI 产品经理定制简历"
}
```

成功返回：

```json
{
  "ok": true,
  "deleted": {
    "resume_id": "...",
    "original_removed": true
  }
}
```

确认名不匹配返回 `CONFIRMATION_REQUIRED`。

## GUI

- 简历列表主标题显示 `display_name`，下方保留原始格式和更新时间。
- 目标岗位标签以蓝色胶囊显示，超过可用宽度自然换行。
- 选中简历的内容页提供“编辑信息”和“删除此简历”。
- 编辑弹窗包含简历名称输入框和以逗号或回车分隔的目标岗位输入。
- 删除弹窗明确说明共享事实会保留，要求输入当前简历名称。
- 删除成功后从列表移除并选择下一份；删除最后一份后进入空简历库状态，但共享事实仍由 Agent 后端保留。
- “删除全部档案”继续保留为独立高风险操作。

## 安全与边界

- API 只接受简历 UUID、名称和字符串标签，不接受磁盘路径。
- 删除文件继续通过私有根目录边界校验。
- 不改变 Agent 使用的共享事实读取接口。
- 不实现岗位数据库绑定、自动标签生成、标签推荐或简历内容编辑。
- 不新增第三方依赖。

## 测试与验收

- schema v4 升级到 v5 后元数据正确回填。
- Repository 和 Service 覆盖名称/标签规范化、非法输入、更新和软删除。
- 删除后简历列表和详情不可见、原文件消失、提取全文清空、预览删除。
- 删除后 `candidate_facts`、`profile_versions` 和其他简历保持不变。
- HTTP API 覆盖 PATCH、DELETE、中文错误和敏感字段不泄漏。
- GUI 覆盖编辑保存、标签展示、精确名称确认、删除后自动选择下一份。
- 浏览器验证真实简历重命名和删除交互时不执行实际删除；实际删除行为由隔离测试数据库验收，避免破坏用户真实简历。
