# 用户反馈、脱敏诊断与问题中心（三阶段）

用户已确认公开验收边界：故障关联脱敏诊断且不含密钥或私密正文；用户只能
提交/查看自己的反馈；指定管理员可以处理反馈，普通用户不能访问管理接口。
按依赖顺序实施，不重写 Agent 循环、权限或会话机制。

## 第一阶段：诊断基础

服务端为每个接口请求生成随机排查编号，忽略客户端伪造编号。失败只保存
编号、时间、所属用户、固定页面/路由类别、状态码、耗时、来源和固定错误类别；
不保存提示词、正文、Cookie、请求网址/查询串、模型原始错误或任意异常字符串。
云端使用现有 PostgreSQL，桌面/隔离演示使用独立 SQLite，禁止云端静默降级。
加入前端集中错误边界、受控错误上报与实时会话错误关联；不采集输入、控制台
或录屏。限频、限量、过期清理仅限新增技术诊断表，日志失效不阻止原业务。

验收：真实 HTTP 错误可用编号查询；跨用户查不到；未捕获错误返回通用消息，
无敏感内容；存储故障仍保留原响应；前端故障与实时错误具有反馈入口。

## 第二阶段：站内反馈

侧栏/窄屏可达的帮助与反馈、故障快捷反馈。文本类型为功能故障/体验建议/其他，
描述有界，明确不要填写私密正文或密钥。用户主动提交，自动附加已确认的故障
编号与页面版本，禁止任意用户/状态字段；服务器验证编号所有权。
保存反馈后返回编号；用户可查看自己的反馈、状态和回复。重复提交幂等。
登录页提供不依赖登录的反馈出口，但匿名入口单独限频，不附带用户数据。
不做截图、任意文件上传、公开反馈墙或外部工单平台同步。

验收：提交/刷新/历史查看闭环；用户间隔离；越权编号不关联；失败不丢草稿；
报错快捷入口和手机入口真实浏览器可用；反馈内容作为纯文本显示。

## 第三阶段：问题中心与基础告警

管理权限由服务端配置的应用用户编号决定，默认无人拥有权限，不按客户端字段
或按钮显示赋权。权限只针对反馈与技术诊断，不授予简历/对话或全库绕过权限。
管理页支持列表筛选、详情关联诊断、回复、状态（待处理/处理中/已修复/不采纳）
及重复问题合并；管理访问和修改另留不含正文的审计。
基础告警包括服务不可达、异常重启、磁盘/内存告警和错误聚合。应用内问题
中心保留告警，服务器独立检查避免主应用宕机漏报；通知目的地和凭据只由
部署管理员配置，默认不外发，仅发送类别、数量与编号，不发送用户材料。
新增接口逐条加入云端白名单，绝不向 Agent 工具开放管理能力。

验收：普通/匿名账号拒绝管理接口；管理员跨用户处理仅限支持数据；用户看到
回复及状态；合并不泄漏其他用户内容；告警去重、冷却、网络故障有界；真实
双身份隔离、浏览器与数据库回归通过。生产管理员账号与外部通知目标待用户
指定，先用独立虚构环境验收，不擅自授予生产权限或发送通知。

## 实施记录与最终交付

各阶段按真实接口/界面进行测试驱动验证与逐项审查，相关回归与生产构建通过
后记录开发日志。保留现有未提交改动，第一版不新增大型依赖。最终交付包含
可运行三阶段代码、数据库迁移、部署/告警配置说明和逐项验收证据。生产发布
另外执行备份与人工身份确认，不以本地完成冒充线上可用。
