# AI 简历分析会话标题设计

## 目标

从岗位详情启动 AI 简历分析后，会话标题固定显示为：

```text
公司 · 岗位名称
```

例如：

```text
字节跳动 · 开放平台运营（短剧方向）实习生
```

该标题用于顶部栏、最近对话、搜索结果及其他复用会话标题的界面，帮助用户按岗位
快速定位分析记录。

## 数据边界

岗位详情页已经持有公司名和岗位名。启动分析时只把这两个字段作为客户端会话命名
元数据传给 `App`：

- Agent Prompt 仍只包含 `job_id` 和 `resume_id`。
- 公司名和岗位名不作为新增模型上下文。
- 不读取或传递简历正文、联系方式、`match_snapshot_id`。
- 不修改 Career Resume Coach 的诊断、追问和改写流程。

## 命名流程

1. `CareerResumeCoachLauncher` 在用户选择已确认简历后，提交岗位 ID、简历 ID、
   公司名和岗位名。
2. `App` 创建新的 Career Conversation，并暂存确定性标题。
3. 收到首个 `turn_start` 后，复用现有 `renameSession` 接口写入标题。服务端在处理
   后续请求前会完成该事件对应的会话持久化。
4. 写入后刷新会话列表，使顶部栏与最近对话立即显示新标题。

命名使用已有会话事件与重命名接口，不修改全局自动标题模型或 WebSocket 协议。
标题写入属于显式重命名，因此后续自动标题不得覆盖；用户手动改名仍可覆盖该
默认标题。命名在模型分析期间即可显示，不等待耗时较长的首轮完成。

公司名或岗位名缺失时分别使用 `未知公司`、`未命名岗位`，避免重新引入模型生成
标题。最终长度继续由现有会话重命名接口限制。

## 历史数据

不执行批量迁移。部署完成后仅定位截图中标题以
`Use the preloaded skill "career-resume-coach"` 开头的异常会话：

- 核对该会话首轮中的 `job_id`。
- 从当前用户可见岗位读取公司名和岗位名。
- 通过现有会话重命名接口精确更新这一条记录。
- 修改前后核对会话 ID，其他历史标题保持不变。

## 错误处理

- 首个 `turn_start` 前连接失败时不写入岗位标题，保留现有回退状态供用户查看错误。
- 重命名失败不影响诊断结果；界面继续使用已有回退标题。
- 历史异常会话无法唯一定位时停止修改，不按标题前缀批量更新。

## 验收

1. 启动 payload 包含公司名和岗位名，但生成的 Agent Prompt 仍只含两个 ID。
2. 新 AI 简历分析首轮完成后，标题为 `公司 · 岗位名称`。
3. 标题不再出现预加载 Skill 指令。
4. 模拟面试、普通 Conversation 和用户手动重命名行为不变。
5. 仅截图中的异常历史会话被修正。
6. GUI 聚焦测试、全量测试、TypeScript 和 Alpha build 通过。
