# 独立岗位雷达页面与档案字段中文化设计

## 1. 目标

本阶段解决两个直接影响产品可用性的缺口：

1. 真实岗位已经存入本地 Career 数据库，但用户只能通过 Agent 对话查询，无法在稳定页面中浏览、筛选和阅读岗位详情。
2. 求职档案的章节标题已经中文化，但对象内部仍直接显示 `birth_date`、`degree`、`end_date` 等英文存储字段。

完成后，OpenCareer 应提供左侧一级“岗位雷达”入口，使用列表与详情同屏布局读取真实岗位数据；求职档案中所有用户可见字段名应显示为中文。

## 2. 已确认产品决策

### 2.1 岗位雷达入口

左侧固定产品入口顺序为：

```text
新建对话
岗位雷达
我的求职档案
搜索
自动任务
```

“岗位雷达”是本地产品页面，不通过向 Agent 发送 prompt 打开，也不依赖模型、MCP 连接或审批状态。

### 2.2 主布局

采用“列表与详情同屏”：

- 页面顶部固定搜索和筛选区域。
- 左侧为分页岗位列表。
- 右侧为当前选中岗位的完整详情。
- 首次加载自动选中当前页第一条岗位。
- 点击其他岗位只更新详情区域，不丢失筛选条件、分页位置或列表滚动位置。

该布局优先服务桌面端连续浏览和比较岗位的场景。窄窗口可以降级为上下布局，但本阶段不单独设计移动端路由。

### 2.3 筛选范围

首版支持：

- 关键词：匹配岗位标题、完整 JD 和要求。
- 公司：单选，来源于本地岗位库已有公司。
- 城市：单选，使用标准化后的岗位城市。
- 招聘类型：全部、社招、校招、实习和数据库中其他已有值。
- 岗位状态：默认“在招中”，可切换为“全部”“已下线”。

筛选变更后回到第一页。关键词输入使用显式搜索提交或短防抖，避免每个按键产生数据库查询。

### 2.4 分页

- 每页固定 20 条。
- 显示结果总数、当前范围、上一页和下一页。
- 后端最大 `limit` 继续保持 100，不为页面解除现有限制。
- 排序沿用现有 Repository：首次发现时间倒序，岗位 ID 作为稳定次序。

本阶段不增加用户可选排序。

### 2.5 岗位详情

详情区展示：

- 岗位标题。
- 公司名称。
- 城市。
- 招聘类型。
- 在招状态。
- 岗位职责。
- 岗位要求。
- 完整 JD 原文。
- 官方来源链接。
- 首次发现时间。
- 最近确认时间。
- 最近变化时间。
- 版本记录摘要。
- 岗位事件摘要。

“查看官网”使用岗位保存的 canonical source URL。`manual://` 等非 HTTP 来源不显示外链按钮。

## 3. 架构

### 3.1 复用边界

岗位页面复用现有：

- `JobService.search_jobs()`。
- `JobService.get_job()`。
- `JobRepository.search_jobs()`。
- `JobRepository.get_job()`。
- Career SQLite 数据库和现有岗位状态模型。

不得为页面复制 SQL、另建岗位索引或绕过 Career Domain Service。

### 3.2 页面 API

OpenWorker Server 新增只读接口：

```text
GET /v1/career/jobs
GET /v1/career/jobs/{job_id}
GET /v1/career/jobs/filters
```

#### 岗位列表

`GET /v1/career/jobs` 接受：

```text
query
company_slug
location
recruitment_type
status
limit
offset
```

Server 将单值参数转换为现有 `JobService.search_jobs()` 所需列表参数。响应保持：

```json
{
  "ok": true,
  "jobs": [],
  "total": 0,
  "limit": 20,
  "offset": 0
}
```

#### 岗位详情

`GET /v1/career/jobs/{job_id}` 调用 `JobService.get_job()`，返回当前岗位、版本和事件。不存在的岗位返回 HTTP 404 和稳定错误码 `JOB_NOT_FOUND`。

#### 筛选选项

`GET /v1/career/jobs/filters` 返回数据库中实际存在的：

- 公司名称和 slug。
- 城市。
- 招聘类型。
- 状态及对应数量。

筛选选项由 Repository 使用 `DISTINCT` 和聚合查询生成，不从 Adapter 配置硬编码，也不调用公网。

### 3.3 错误处理

页面 API 使用稳定中文错误：

- `JOB_NOT_FOUND`：岗位不存在或已被删除。
- `INVALID_INPUT`：筛选或分页参数无效。
- `PERSISTENCE_ERROR`：本地岗位数据读取失败。

未知异常记录服务端 traceback，但响应不暴露 SQLite 路径、SQL 或 Python 堆栈。

## 4. GUI 设计

### 4.1 Surface

App 新增 `jobs` surface，与 `profile`、`scheduled`、`settings` 同级。新增 `CareerJobsView`，不嵌入会话主区域，也不显示对话右侧栏。

### 4.2 页面状态

页面必须处理：

- 初始加载。
- 有结果。
- 筛选后无结果。
- 岗位列表读取失败。
- 岗位详情读取失败。
- 当前选中岗位在刷新后不再存在。

列表成功但详情失败时保留列表，不将整个页面替换为错误页。

### 4.3 列表区域

每条岗位卡片显示：

- 岗位标题。
- 公司。
- 城市。
- 招聘类型。
- 状态。
- 最近确认或最近变化时间。

当前选中卡片有明确的选中态。列表不展示完整 JD，避免每页传输和渲染大量重复文本。

### 4.4 详情区域

详情按以下层级展示：

1. 标题、公司、城市、类型和状态。
2. 官方来源和时间信息。
3. 职位职责。
4. 职位要求。
5. 完整 JD。
6. 版本与变化记录。

职责和要求为空时显示“原始 JD 未拆分该部分”，继续提供完整 JD，不把字段缺失误报为页面错误。

## 5. 求职档案字段中文化

### 5.1 映射策略

新增集中纯函数，例如：

```typescript
careerProfileFieldLabel(key: string): string
```

`CareerProfileView` 的递归对象渲染统一调用该函数，不在组件中散落条件判断。

### 5.2 显式映射

至少覆盖当前 Career Vault 可能出现的字段：

| 字段 | 中文 |
|---|---|
| `name` | 姓名 |
| `phone` | 手机号 |
| `email` | 邮箱 |
| `birth_date` | 出生日期 |
| `location` | 所在地 |
| `summary` | 个人简介 |
| `github` | GitHub |
| `school` | 学校 |
| `degree` | 学历 |
| `major` | 专业 |
| `gpa` | GPA |
| `ranking` | 排名 |
| `start_date` | 开始时间 |
| `end_date` | 结束时间 |
| `company` | 公司 |
| `title` | 职位 |
| `description` | 描述 |
| `responsibilities` | 职责 |
| `achievements` | 成果 |
| `project_name` | 项目名称 |
| `role` | 担任角色 |
| `technologies` | 技术栈 |
| `skill` | 技能 |
| `level` | 熟练程度 |
| `evidence` | 佐证 |

品牌专名 `GitHub`、`GPA` 保持通用写法。

### 5.3 未知字段

未知字段不得直接显示 snake_case。兜底规则：

1. 去除首尾空白。
2. 将 `_` 和 `-` 转为空格。
3. 对无法映射的字段显示可读化结果。

兜底仅用于兼容未来字段；新增正式 Career Vault 字段时仍应补充显式中文映射和测试。值、用户内容、公司名、文件名和 URL 不翻译。

## 6. 安全与性能

- 页面 API 只读，不需要审批。
- 不接受客户端 SQL、排序列或文件路径。
- 参数继续经过现有 `JobSearchFilters` 和 Service 限制。
- 列表每页只返回摘要字段；完整 JD 仅在选择岗位后通过详情 API 获取。
- 所有外链使用数据库保存的官方来源 URL，并以新窗口打开。
- 不自动访问招聘官网，不触发实时 crawler。

## 7. 测试与验收

### 7.1 后端

- Repository 筛选选项去重、排序和数量正确。
- HTTP 列表参数正确转换为 Service filters。
- 默认只查询 `active` 岗位。
- 关键词、公司、城市、类型、状态和分页可组合。
- 详情返回版本、事件和官方 URL。
- 不存在岗位返回 `JOB_NOT_FOUND`。
- 未知异常只写日志，不泄露内部信息。

### 7.2 GUI

- 左侧“岗位雷达”一级入口可打开独立页面。
- 初次加载默认在招岗位并选中第一条。
- 搜索和筛选更新列表并重置分页。
- 点击列表项只更新右侧详情。
- 上一页、下一页边界正确。
- 无结果、列表错误和详情错误使用中文状态。
- 官方链接仅对 HTTP/HTTPS URL 显示。

### 7.3 档案字段

- 基本信息、教育、工作、项目和技能中的已知字段全部显示中文标签。
- 未知 snake_case 字段不原样显示下划线。
- 字段值不被翻译或改变。
- 中文文案审计继续通过。

### 7.4 最终验收

- Career 和 Server 相关后端测试通过。
- GUI 全量测试通过。
- TypeScript 与 production build 通过。
- `git diff --check` 通过。
- 浏览器验证真实岗位列表、组合筛选、详情和官方链接。
- 浏览器验证档案页不存在截图中的英文 snake_case 字段。
- 干净浏览器标签页控制台 0 error。

## 8. 非目标

- 不实现岗位收藏。
- 不实现简历匹配评分。
- 不实现申请进度跟踪。
- 不实现自动投递或招聘网站登录。
- 不改变 crawler 调度和数据采集。
- 不增加全文搜索引擎、向量数据库或新依赖。
- 不实现用户可配置排序。
