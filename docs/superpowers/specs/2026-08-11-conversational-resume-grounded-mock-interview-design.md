# 对话式、简历驱动的模拟面试升级总设计

## 目标

把当前模拟面试从独立操作页升级为 OpenCareer 中的一类标准对话任务：

```text
目标 JD + 已确认简历
→ 岗位差异化面试计划
→ 文字或语音多轮对话
→ 结构化复盘
→ 可查询的历史面试记录
```

AI 面试官必须同时理解岗位要求和简历中的具体经历，并根据岗位类型采用不同的
深挖方向。后续再把现有“录音后整段转写”升级为自动轮流的实时语音。

## 已确认产品决策

1. 采用“标准 Career Conversation + 可折叠右侧面试上下文”布局。
2. 模拟面试问题和回答以正常 assistant/user 消息呈现。
3. 支持文字回答、现有录音转写回答，以及后续实时语音回答。
4. 存在可安全引用的简历证据时，首题必须结合目标岗位和最相关的已确认经历；完全
   无证据时退化为岗位知识问题，不得暗示用户做过相关项目。
5. 标准难度需要对核心项目进行连续多轮深挖。
6. 算法、研发、产品岗位采用不同的探查维度；混合岗位可启用多个 track。
7. 面试中不展示评分、问题答案或辅导。
8. 每场面试结束后生成逐题复盘、准备清单和不可变历史记录。
9. 默认不保存原始音频；面试回答不得自动写回 Career Vault。
10. 实时语音首版采用自动轮流对话，不支持用户打断 AI 播报。

## 为什么不能只修改系统提示词

当前 `mock-interview` Skill 声称可以读取已确认简历，但实际
`InterviewSession.blueprint` 只包含岗位要求、`fact_path` 和匹配状态，不包含这些
路径对应的事实摘要。模型看到 `project[0].highlights[0]`，却看不到该项目具体做了
什么。

同时，Start Workflow 把首题硬编码成“请简单介绍一下你自己”。因此即使岗位和简历
已经绑定，第一轮也不会体现任何针对性。

正确修复必须同时覆盖：

- 结构化且脱敏的简历事实输入。
- 岗位类型和深挖计划。
- Prompt/Skill 决策流程。
- Service 对引用、深度和状态的硬校验。
- 对话界面、复盘和历史记录。

## 子系统拆分

### 子系统 1：JD/简历驱动的面试智能

负责：

- Blueprint v2。
- 岗位 `role_tracks`。
- 简历 `evidence_cards`。
- 结构化 `probe_plan`。
- 多轮深挖状态。
- Career Persona、`mock-interview` Skill 和 GUI task prompt。
- 问题引用、维度和深度校验。

这是第一优先 Gate。详细规格见：

`docs/superpowers/specs/2026-08-11-resume-grounded-interview-intelligence-design.md`

### 子系统 2：对话式面试、复盘与历史

负责：

- 不再把 `surface="interview"` 作为主要用户体验。
- 将面试问题和回答投影到绑定的 Career Conversation。
- 使用标准 Transcript、Composer、权限审批和 TurnEngine 状态。
- 在右侧面板展示岗位重点、简历关注项目、覆盖进度和语音状态。
- 结束后在对话内展示复盘卡片。
- 新增“面试记录”入口和查询 API。

该子系统不改变 Agent Loop，也不创建第二套 Conversation 存储。

### 子系统 3：实时自动轮流语音

负责：

- 浏览器/Tauri PCM 流式上传。
- 服务端有状态语音 WebSocket。
- 豆包流式 ASR partial/final transcript。
- 静音检测和本轮自动结束。
- final transcript 自动提交到现有 Interview/TurnEngine。
- 下一题生成后的流式 TTS 播放。
- 断线、取消、超时和降级到文字模式。

首版不实现全双工 RTC、barge-in 或用户说话打断 AI。

## 对话界面

### 主对话

面试仍绑定一个真实 OpenWorker Session：

- AI 问题显示为 assistant 消息。
- 用户文字或语音回答显示为 user 消息。
- MCP 调用和审批继续显示在标准工具/审批组件中。
- `session_id`、`turn_id` 和 CAS `version` 作为内部控制信息传递，不作为用户可见
  文案。
- 提前结束、刷新和报告生成作为对话任务动作，不创建不明来源的独立表单流程。

### 右侧面试上下文

默认展开，可折叠。只展示：

- 公司、岗位、简历名称、难度和轮次。
- JD 重点。
- 当前关注的简历项目。
- 已覆盖、进行中和未覆盖的 probe target。
- 语音模式状态。

不得展示：

- 隐藏评分。
- evaluation issues。
- 下一题答案提示。
- 联系方式、私有路径或完整简历正文。

## 岗位差异化

岗位可启用一个或多个 track：

### `algorithm`

- 数据来源与构造。
- 模型或算法选择。
- 训练和推理流程。
- 实验设计和对照。
- 评测指标、误差分析。
- 推理性能和成本优化。

### `engineering`

- 系统架构和模块边界。
- 核心代码、接口和数据结构。
- 并发、事务和一致性。
- 性能、容量和可观测性。
- 故障处理、可靠性和安全。
- 技术取舍和替代方案。

### `product`

- 用户和业务问题。
- 产品目标和策略。
- 功能、流程和交互设计。
- 评测方案和成功指标。
- 实验、反馈和迭代。
- 优先级、资源和商业取舍。

### `general`

- 个人职责。
- 行动和协作。
- 结果证据。
- 决策和复盘。

分类不确定时回退 `general`，不得让模型猜测岗位类型。

## 多轮深挖

一个核心项目的标准探查链为：

```text
背景与目标
→ 个人职责
→ 岗位特定细节
→ 结果与验证
→ 取舍、失败或复盘
```

每轮只能提出一个主要问题。难度控制同一 target 的最大深度：

- simple：最多 1 次追问。
- standard：连续 2–3 层。
- deep：连续 3–4 层。

若上一回答含糊、只说“我们”、缺少个人行动或证据，优先继续当前 target。当前 target
达到目标深度后，再切换到重要 JD 缺口、另一项目或岗位场景题。

## 复盘

面试结束后生成三个层级。

### 总览

- 岗位、简历、难度、轮次和数据版本。
- JD 要求覆盖情况。
- 简历项目深挖情况。
- 表达、结构、岗位深度和证据充分度总结。

不得生成录用概率、胜任率或无依据的综合结论。

### 逐题复盘

每题包含：

- 原问题和原回答。
- 考察目标。
- 有效部分。
- 不足及原因。
- 缺少的事实、指标或细节。
- 推荐回答结构。
- 只基于原回答和已确认事实的参考优化。

### 准备清单

分为：

- 表达练习。
- 经历补证。
- 知识复习。
- 资料调研。
- 下一次模拟重点。

资料调研只生成主题和原因。未经用户确认的外部资料不得写入 Career Vault，也不得
变成用户经历。

## 面试历史

“面试记录”提供：

- 按公司、岗位、简历、日期和状态筛选。
- 显示轮次、难度、主要薄弱项和完成状态。
- 重新打开绑定 Conversation、逐字稿和完整复盘。
- 创建新面试，不覆盖旧记录。

每场记录保存：

- InterviewSession 和 InterviewTurn。
- job/resume/snapshot/conversation ID。
- 岗位与简历版本。
- Blueprint。
- 问答、隐藏评价和复盘。
- Artifact SHA-256。

默认不保存原始音频。

## 隐私和事实边界

- 只使用已确认简历 section。
- evidence card 排除敏感 key 和敏感 value。
- 不返回电话、邮箱、地址、身份证、私有文件路径。
- 面试 transcript 是训练记录，不是已确认事实。
- 模型不得把回答中的新信息自动写回 Career Vault。
- 复盘中的参考优化不得添加虚构指标、日期、角色或成果。
- 所有会改变 Session 状态的 MCP 工具继续使用 CAS 和权限机制。

## 错误和恢复

- stale job/resume/snapshot：阻止新面试，要求重新匹配。
- 无可靠岗位分类：使用 `general`。
- 无可用简历证据：只允许岗位知识/场景问题，不声称用户做过相关项目。
- Agent 生成非法引用或深度：Service 拒绝，不放宽校验。
- Conversation 断开：InterviewSession 保留，重连后从当前 unanswered turn 恢复。
- 用户中断：保留已有问答，状态标记 interrupted。
- 明确提前结束且至少有一题已回答：允许生成正式复盘。
- ASR/TTS 失败：保留文字输入。

## 实施顺序

1. 完成子系统 1 的设计、TDD、真实三岗位 Gate。
2. 完成子系统 2 的对话迁移、复盘与历史。
3. 为子系统 3 单独完成协议和状态机设计。
4. 实现实时自动轮流语音。

在子系统 1 通过前，不开始实时语音状态机。

## 总体验收

- 面试看起来是标准 Career Conversation。
- 文字和语音回答共享同一 InterviewSession。
- 存在 evidence card 时，首题同时针对岗位和简历经历；无证据时安全退化。
- 核心项目出现连续多轮、岗位特定的深挖。
- 算法、研发、产品三类 fixture 和真实模型 Gate 均通过。
- 复盘明确指出回答不足、准备项和资料调研项。
- 每场面试可在“面试记录”中重开。
- 不泄露敏感简历信息，不保存原始音频，不虚构经历。
