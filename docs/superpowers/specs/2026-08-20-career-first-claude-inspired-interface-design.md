# OpenCareer Career-first 暖色编辑台界面设计

## 1. 目标

将现有 OpenWorker 风格外壳改造成以求职工作流为中心的 OpenCareer 界面。视觉采用已
批准的方案 B“暖色编辑台”：参考 Claude 的温和纸张感、衬线标题、低饱和暖色和充足
留白，但不复制 Claude 的商标、文案或逐像素布局。

成功标准：

1. 用户第一眼识别到 OpenCareer，而不是换了品牌名的 OpenWorker。
2. 左侧导航只呈现求职高频入口与最近对话。
3. OpenWorker Cloud 登录、收件箱和通用管理入口不再出现在主界面。
4. 对话、岗位雷达、求职档案和模拟面试使用同一套视觉语言。
5. 桌面与 `375×812` 移动视口均无横向溢出、遮挡或不可达操作。

## 2. 范围

### 2.1 本轮移除的用户入口

Career-first 外壳不再展示：

- OpenWorker Cloud 登录、登录状态、退出登录和未登录提示。
- 独立“收件箱”页面入口及底部收件箱计数 Chip。
- “连接器”“自动任务”“活动记录”的主导航和账户菜单入口。
- Agent 分组、Agent 管理和通用 OpenWorker Persona 选择器。
- `BETA` 品牌标签。

主导航固定为：

1. 新建对话。
2. 岗位雷达。
3. 求职档案。
4. 最近对话与搜索。
5. 底部设置。

### 2.2 保留的安全与兼容能力

- 审批卡片继续在当前对话中展示和处理。
- `ask_user`、目录授权、计划审批和工作区信任门禁不变。
- Inbox 后端 API、数据库记录和历史页面组件本轮不删除。
- 已存在的 unattended/automation 数据不迁移、不删除。
- 桌面端与 Alpha 共用 React 界面；Origin、Token、PostgreSQL、Redis 和 Caddy
  配置不变。

这些约束将“界面取消收件箱”与“关闭审批安全机制”明确分开。

## 3. 信息架构

### 3.1 桌面布局

使用三段式工作区：

- 左侧 `252px` 暖灰导航。
- 中间自适应主内容区，常规对话正文最大宽度 `760px`。
- 模拟面试或 Artifact 打开时使用右侧上下文栏；不打开时主内容区居中。

左侧顶部只保留 OpenCareer 字标、收起和搜索图标。其后依次为主操作和求职入口，
再显示最近对话。底部单独放置设置图标，不再使用“账户/未登录”菜单。

### 3.2 移动布局

- 主内容占满视口。
- 左侧导航变成抽屉，通过顶部菜单图标打开。
- 右侧面试进度使用现有移动抽屉，不与 Composer 同时占用横向空间。
- 页面左右安全间距至少 `16px`；所有固定控件必须落在 `375px` 视口内。

### 3.3 路由兼容

`App` 内部既有 surface 状态继续保留，避免扩大改动面。主导航不再能进入
`inbox/integrations/scheduled/audit`，但旧状态分支暂时保留，便于后续决定是否彻底
删除对应功能。若刷新或旧状态落入隐藏 surface，界面回退到 `session`。

## 4. 视觉系统

### 4.1 色彩

浅色主题核心令牌：

```css
--paper: #f7f4ed;
--panel: #fffdf8;
--sidebar: #eee9df;
--ink: #2f2b26;
--muted: #6f685f;
--faint: #9a9288;
--line: #ded6ca;
--line-strong: #cfc4b5;
--accent: #b65f42;
--accent-soft: #f3e4da;
--solid: #ebe5da;
--on-solid: #302c27;
```

状态色保留语义差异：

- 成功/已完成：低饱和绿。
- 当前/主操作：陶土橙。
- 警告：琥珀色。
- 危险：暗红。

不使用紫色渐变、蓝色主导、大面积深色背景、装饰光球或玻璃拟态。

深色主题继续可用，但同步为暖黑和低饱和陶土强调色，不保留当前蓝灰体系。

### 4.2 字体

- 品牌、空状态主标题、面试问题：本地优先的中文友好衬线栈
  `"Songti SC", "STSong", "Noto Serif CJK SC", Georgia, serif`。
- 正文、导航、控件：系统无衬线栈，保证中文清晰和桌面打包稳定。
- 代码和技术输出：现有等宽字体。
- 不新增在线字体请求或运行时字体依赖。
- 字间距固定为 `0`；仅小型英文 eyebrow 可使用轻微正字距。

### 4.3 形状与层级

- 常规卡片圆角不超过 `8px`。
- Composer 圆角 `12px`，作为唯一更柔和的核心输入容器。
- 页面 section 不包装成浮动卡片；仅重复岗位项、审批、弹窗和独立工具使用卡片。
- 阴影只用于 Composer、弹窗和悬浮导航，页面主体通过边框和底色分层。
- 主按钮使用陶土色实底；次按钮使用透明或暖白背景。

## 5. 核心界面

### 5.1 左侧导航

`Sidebar` 改为 Career 专用壳：

- “新建对话”为宽按钮，陶土色只用于图标或 hover/active，不使用当前高饱和蓝色。
- “岗位雷达”“求职档案”为固定入口。
- “最近对话”保持重命名、置顶、归档和删除能力。
- 去掉自动任务 Band、Persona 分组和账户状态请求。
- 底部设置使用齿轮图标加“设置”文本；无弹出账户菜单。

移除入口后，Sidebar 不再轮询 Cloud 状态、Inbox 解锁状态或 Automations，减少 Alpha
中的无意义请求和预期 `403` 噪声。

### 5.2 对话首页

`CareerWelcome` 改成编辑台式首页：

- 标题为衬线大字，正文保持简短。
- 高频动作从五个收敛为三个：发现岗位、导入/管理简历、分析 JD。
- “岗位雷达”和“求职档案”不在首页重复做第二组导航入口。
- 动作采用分隔列表，不使用五张大卡片。

### 5.3 对话与 Composer

- Assistant 内容取消工具式灰色层级，使用干净正文排版。
- 用户回答保持暖灰气泡，与纸张背景形成轻微差异。
- Composer 使用暖白背景、细边框和轻阴影；发送按钮为陶土色圆形图标。
- 模型、上下文等低频状态降低对比度，语音与附件仍可见。
- 思考时间只展示安全的阶段耗时，不展示隐藏推理文本；本轮不新增耗时功能。

### 5.4 岗位雷达与求职档案

- 复用统一背景、标题、分段控件、输入框和按钮令牌。
- “全部岗位 / 收藏箱”保持现有交互，active 状态改为陶土强调。
- 岗位列表和详情降低卡片感，优先使用分隔线、留白和两栏扫描结构。
- 详情继续只显示一个完整 `JD`，不恢复职责/要求重复区块。
- 档案页签、简历项和版本记录沿用现有数据流，只改视觉。

### 5.5 模拟面试

- 面试问题使用衬线标题，题型标签使用小号陶土色文本。
- 右侧五题进度保持蓝/绿/灰的旧语义要求时，改为更协调的
  “低饱和绿=完成、陶土色=当前、暖灰=待生成”；不改变状态计算。
- 不增加“重播问题”“提前结束”或独立流程状态。
- 移动端仍通过抽屉查看进度，Composer 始终可操作。

## 6. 组件与文件边界

主要修改：

- `surfaces/gui/src/components/Sidebar.tsx`
  - 删除 Cloud/Inbox/Automation 导航状态与轮询。
  - 输出精简 Career 导航。
- `surfaces/gui/src/App.tsx`
  - 简化 Sidebar props。
  - 对隐藏 surface 增加 session 回退。
- `surfaces/gui/src/styles.css`
  - 更新全局视觉令牌、布局、对话、Composer 和响应式样式。
- `surfaces/gui/tailwind.config.js`
  - 同步字体与必要令牌映射，不新增依赖。
- `surfaces/gui/src/components/CareerWelcome.tsx`
  - 收敛首页动作和编辑台布局。
- `CareerJobsView.tsx`、`CareerProfileView.tsx`、
  `ConversationInterviewBar.tsx`、`InterviewProgressPanel.tsx`
  - 仅调整与新视觉系统冲突的局部类名。

不在本轮重构 `App.tsx` 的会话生命周期、不改 API 契约、不删除后端模块。

## 7. 测试策略

所有行为修改执行 RED → GREEN：

1. Sidebar 测试先断言 Cloud 登录、收件箱、连接器、自动任务、活动记录和账户状态不再
   出现，同时设置、岗位雷达、求职档案和最近对话仍可用。
2. App 测试验证旧隐藏 surface 回退到 session，对话内审批卡片仍能处理。
3. CareerWelcome 测试验证动作收敛为三个，且原直接能力仍正确调用。
4. 现有岗位、档案、面试和 Composer 聚焦测试全部通过。
5. GUI 全量 Vitest、`npx tsc` 和 `bash deploy/build-frontend.sh` 通过。
6. Playwright 在 `1440×900`、`1024×768`、`375×812` 三个视口检查：
   - 无横向溢出。
   - 导航可打开/关闭。
   - 岗位、档案、对话可达。
   - 模拟面试进度和 Composer 不遮挡。
   - 控制台 page error 为 0。
   - 隐藏入口在 DOM 和可访问树中均不存在。

## 8. 发布与回滚

本轮只发布 Alpha 前端静态产物，不重建后端镜像。发布前保存当前 `deploy/web` 目录，
新产物通过 SHA-256 清单后原子替换。发布后验证：

- `/_openworker/v1/health` 仍为 PostgreSQL/Redis ready。
- 后端和 Caddy restart count 不变。
- Alpha 不新增非预期 `403`、WebSocket 错误或静态资源 `404`。

若浏览器 Gate 失败，直接恢复发布前静态目录；无需数据库回滚。

## 9. 非目标

- 不删除 Inbox、Connector、Automation 或 Audit 后端 API。
- 不关闭或放宽审批、安全门禁、Origin 和 Token 校验。
- 不实现新的账号登录系统。
- 不增加在线字体、图像或前端依赖。
- 不修改岗位、简历、对话或面试的数据模型。
- 不在本轮实现安全阶段耗时展示。
