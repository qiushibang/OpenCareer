# 岗位筛选、简历库与侧栏搜索优化设计

## 目标

修复岗位雷达中多城市岗位被当成单个筛选项的问题，将招聘类型完整中文化并用标签表达；把单一求职档案页面扩展为可切换多份已确认简历的简历库；将对话搜索从侧栏独立导航项收敛为品牌栏图标。

## 产品决策

### 城市筛选

- 一个岗位可以属于多个城市。
- 对已有 `locations_json` 中的每个字符串继续按 `、`、中文逗号、英文逗号、分号和斜杠拆分。
- 简单城市名移除末尾“市”，因此“北京”和“北京市”统一展示为“北京”。
- 带区县或其他层级的文本不做猜测式地理推断。例如“浙江 拱墅区”原样保留，避免把未知行政层级错误映射为城市。
- 筛选项计数按岗位去重。同一岗位即使重复出现同一城市，也只给该城市增加一次计数。
- 选择任一拆分城市时，包含该城市的多城市岗位必须命中。
- 新写入岗位在通用标准化阶段使用同一纯函数拆分；已有数据由查询层兼容，不要求破坏性迁移。

### 招聘类型

内部枚举继续保持兼容：

| 内部值 | 中文 |
|---|---|
| `experienced` | 社会招聘 |
| `social` | 社会招聘 |
| `campus` | 校园招聘 |
| `internship` | 实习 |
| 空值或未知值 | 类型未标注 |

岗位列表中的招聘类型始终显示为胶囊标签：

- 校园招聘：蓝色。
- 实习：紫色。
- 社会招聘：青色。
- 类型未标注：灰色。

岗位状态使用独立绿色或灰色标签。筛选下拉框与详情页只显示中文，不泄露内部枚举。

### 多简历档案

Career Vault 继续只有一个候选人事实库。姓名、教育和工作经历等真实事实不能因为针对不同岗位制作简历而复制成多套互相冲突的数据。

每个已确认的 `resume_import` 作为一份独立简历文档：

- 简历 ID 使用现有 import UUID，不暴露上传 token 或私有路径。
- 名称默认使用原始文件名。
- 简历内容来自该 import 对应 preview 的最终 proposal，并只返回已确认章节。
- 每份简历可查看自己的原文件和该 import 产生的确认版本。
- 新导入的不同内容会成为新简历，不覆盖简历库中的旧文档。
- 现有 `/v1/career/profile` 保持为 Agent 使用的当前事实档案，避免破坏 MCP 和申请材料链路。

新增只读页面 API：

- `GET /v1/career/resumes`
- `GET /v1/career/resumes/{resume_id}`
- `GET /v1/career/resumes/{resume_id}/versions`
- `GET /v1/career/resumes/{resume_id}/original`
- `GET /v1/career/resumes/{resume_id}/original/content`
- `GET /v1/career/resumes/{resume_id}/original/download`

“我的求职档案”页面改为：

- 顶部“新增简历”按钮。
- 左侧简历列表，显示文件名、格式、确认时间和已确认章节。
- 右侧显示当前选中简历的“简历内容、原始简历、版本记录”。
- 首次进入自动选择最近更新的简历。
- 暂不加入重命名、目标岗位标签、单份删除和简历比较。这些能力需要单独设计，避免本轮扩大写操作和删除风险。

### 侧栏搜索

- 删除“搜索”独立导航行。
- 在展开侧栏顶部 `OpenCareer BETA` 右侧放置搜索图标。
- 点击图标继续打开现有 `SearchModal`，不修改搜索范围、快捷键或会话搜索实现。
- 侧栏折叠时继续使用主区域顶部已有的搜索图标。

## 架构边界

- 城市拆分使用 Career Domain 纯函数，Repository 和 crawler normalize 复用。
- 招聘类型中文和标签样式由 GUI 单一 helper 管理。
- 多简历读取放在 `ResumeRepository` 和 `ResumeService`，FastAPI 仅做薄路由与稳定错误映射。
- 不修改 TurnEngine、Provider Router、MCP Client、权限系统或会话搜索核心。
- 不增加第三方依赖。

## 安全与错误处理

- 简历 API 只接受数据库 UUID，不接受本地路径。
- 原文件读取继续校验解析后的路径位于私有简历根目录内。
- 默认返回的简历内容继续遮罩敏感字段；只有显式 `include_sensitive=true` 才返回完整已确认内容。
- 找不到简历返回 `RESUME_NOT_FOUND` 和中文 404。
- 原文件缺失返回 `ORIGINAL_NOT_FOUND`，不泄露磁盘路径。
- 城市筛选不拼接 SQL；查询参数继续使用绑定变量。

## 测试与验收

### 自动测试

- 城市纯函数覆盖多分隔符、去重、简单“市”后缀和复杂行政文本。
- Repository 筛选元数据验证多城市拆分计数，选择任一城市均命中同一岗位。
- GUI 验证招聘类型不再显示 `experienced`，每个岗位都有中文类型标签。
- Resume Repository、Service 和 HTTP API 验证两份已确认简历可分别列出、读取内容、原文件和版本。
- GUI 验证简历列表自动选择、切换后内容与原文件请求使用对应 ID。
- Sidebar 验证独立搜索行消失，品牌栏搜索图标仍打开搜索弹窗。

### 浏览器验收

- 城市下拉不再出现“上海市、北京市”这类组合项。
- 选择北京、上海中的任一城市时，多城市岗位均能出现。
- 岗位卡片显示“社会招聘/校园招聘/实习/类型未标注”彩色标签。
- 求职档案页面可切换至少两份真实已确认简历。
- `OpenCareer` 右侧有搜索图标，侧栏中没有独立“搜索”行。
- 干净标签页控制台 0 error。

## 非目标

- 不引入地理编码服务或完整行政区划数据库。
- 不根据区县猜测所属城市。
- 不实现简历自动改写、简历匹配评分、单份删除、重命名或比较。
- 不改变事实确认流程和 Agent 对真实经历的约束。
