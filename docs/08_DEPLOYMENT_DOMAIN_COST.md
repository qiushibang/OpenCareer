# 08 — 低成本部署、域名与备案

> 文档状态：2026-08-26 当前方案。操作步骤以
> [`19_DOMAIN_AUTHING_LAUNCH_RUNBOOK.md`](19_DOMAIN_AUTHING_LAUNCH_RUNBOOK.md) 为准。

## 1. 当前形态

- 本地桌面版继续使用本地存储，不强制登录。
- 阿里云中国内地服务器当前只保留 `http://203.0.113.10:18080` 自测入口。
- 云端使用单个后端、PostgreSQL 和 Redis；公开岗位是共享目录，对话、简历、收藏、申请进度和面试记录按 `user_id` 隔离。
- 备案通过后的正式入口为 `https://app.opencareer.online`，由 Authing 提供 OpenID Connect 登录。
- Crawler 是可选 profile，在 2 GB 内存机器上默认不常驻。

## 2. 备案审批期间

域名可以购买、备案和准备 Authing 配置，但中国内地服务器上的首备案网站在审批通过前不得使用域名对外提供访问。因此当前不做 DNS 切换、不开放域名流量，也不把 18080 地址分发给测试用户。

18080 使用明文 HTTP，并由反向代理注入共享 Alpha Token；它只适合本人使用虚构数据验收，不适合真实简历或多人访问。

## 3. 正式域名与登录

正式产品只使用：

```text
https://app.opencareer.online
```

域名请求不注入共享 Token。用户完成 Authing 授权码登录后，后端把 `(issuer, subject)` 映射为稳定内部用户，并签发只保存哈希的应用会话。HTTPS、精确 Origin 白名单和 PostgreSQL 租户上下文共同构成隔离边界。

## 4. 成本与扩容

当前阶段避免 Kubernetes、微服务、向量数据库、消息队列和对象存储。主要成本只包括域名、现有服务器、模型调用和可能的 Authing 套餐。

出现以下信号再扩容：

- Crawler 与在线请求频繁争抢内存：先把 Crawler 改为按需任务，再考虑把服务器升到 4 GB。
- 简历原件使数据库备份明显变大：再评估对象存储，并保持用户级访问控制。
- PostgreSQL 连接或查询成为实际瓶颈：先用指标和慢查询证据优化，不提前拆服务。

## 5. 合规与备份

备案通过后展示真实备案号并链接工信部备案系统；网站开通后按要求完成公安联网备案。产品继续定位为个人求职辅助和官方公开岗位检索，不提供企业入驻、候选人交易、代招聘或自动代投。

上线和每次身份迁移前必须同时备份 PostgreSQL、私有文件卷、Caddy 数据卷和部署配置。真实密钥只在服务器 `.env` 中保存，备份时加密且不得提交仓库。
