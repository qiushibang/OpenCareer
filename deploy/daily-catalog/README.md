# 每天 04:00 从零采集完整岗位目录

这个独立任务取代“旧岗位库定期导出”的新部署路线。它不运行网站、不连接生产数据库，
也不接收用户简历、模型密钥或通知渠道。旧爬虫和小时级导出任务不要同时写同一个公共目录。

每天北京时间 04:00 开始新一代采集，默认没有随机延迟。当天用空数据库请求所有注册
官方来源；失败或大来源未完成时保存本代检查点，15 分钟后继续。重启恢复本代进度；
下一天到04:00由独立监督进程终止旧代次剩余工作，再重新建空库；慢来源不延迟新一天启动。四点是开始时间，全量核验可能需要数小时。

只有全部来源成功、每条当前岗位的官网观测都属于本次扫描，才会原子替换清单。
失败继续提供上一版，并在本地 `status.json` / `runs/<日期>/run.json` 标明未完成来源。
不会把上次岗位或八月确认时间重写为今天；不绕过验证码或访问限制。
退避从每个来源实际失败时间计算；长来源结束时已过退避期的失败来源立即进入下一轮，最近失败的来源仍等待满15分钟，不额外重复等待。

## 本地验证

使用项目虚拟环境并安装既有 browser 可选依赖及 Chromium（见项目安装指南）：

```bash
python -m extensions.career_mcp.daily_catalog --data-dir ./catalog-worker --output ./catalog-feed
```

单次推进并返回退出码：

```bash
python -m extensions.career_mcp.daily_catalog --data-dir ./catalog-worker --output ./catalog-feed --once
```

退出码 0 表示当天完整目录已发布，3 表示未完成。程序的操作系统文件锁阻止同目录双进程。
目录必须全新且专用于本任务，不能指向现有用户或网站数据目录。不要手工改检查点或更新时间。

Mac 验收时可使用 `caffeinate -i python -m extensions.career_mcp.daily_catalog --data-dir ./catalog-worker --output ./catalog-feed` 临时防止系统自动休眠；不修改永久电源设置。同目录只运行一个实例。休眠或断网期间无法采集，唤醒后会补启动当前代次，不把昨日结果当作今天已运行。逐来源进度实时保存在 status.json，包含无凭据的错误类型。

## 独立服务器容器

`compose.yml` 是单独的编排项目，不合并网站编排，不挂载网站数据库或隧道。
输出目录应为自己的静态文件目录；先用测试目录核对，之后再切换正式目录。
容器以 10001 用户写入，创建输出目录后给该用户写权限。例如在仓库根目录：

```bash
mkdir -p ./catalog-feed
sudo chown 10001:10001 ./catalog-feed
PUBLIC_CATALOG_OUTPUT="$(pwd)/catalog-feed" docker compose -f deploy/daily-catalog/compose.yml up -d --build
```

命名数据卷首次挂载由镜像目录权限初始化；若宿主机设置改变，核对 `/collector` 对10001可写。
容器限制一个处理器、1 GiB内存，运行浏览器时仍应根据宿主机容量评估。构建验证不等于已部署。

把输出目录以 HTTPS 静态目录提供，保留整个 `sources/` 及 `manifest.json`。
正式发布到独立的 `/public/jobs/v2/` 目录，不覆盖已有第一版 `/public/jobs/v1/`，避免影响旧客户端或当前网站。新版客户端优先检查第二版；仅新端点尚未安装（404或站点首页回退）时读取第一版，并在同步状态记录 legacy_fallback。新端点的数据损坏或访问错误不能伪装成成功回退。客户端每次同步都会重新检查第二版，安装后可自动切换。
新旧压缩文件不可就地覆盖，保留旧文件以服务已读取旧清单的客户端。

## 同步与“昨天新增”

本地用户默认共享模式点击「一键同步岗位」，只下载服务端最新完整目录，不会让每台电脑
重复抓官网。第二版目录同步完整当前集合；缺失岗位退出在招集合，但保留其申请和收藏。
旧第一版目录继续兼容，不推断缺失岗位下线。

`public-history/` 是与每天空库分离的公共变化账本。它保留身份和前后完整来源比较，导出当前
岗位最近90天的新增、更新、重开、补录事件。因此首次安装的用户也能查询“昨天新增的字节
北京产品岗”；初始基线不能虚构成当天新增，中断超过48小时后的新出现记录按补录处理。
自然语言筛选继续由既有 Agent 和岗位查询工具完成，不需要为采集配置模型。

验收必须分别记录：自动测试、真实官网整轮结果、本地目录空库导入、正式 HTTPS 下载。
只有最后两项均实际完成，才能宣称开源用户默认同步拿到最新完整岗位。
